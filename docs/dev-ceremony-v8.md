# Trusted setup for the V8 circuits: development keys, not a production ceremony

**Do not use these keys to protect real funds.** They exist so the V8 pools can be tested end to end on the Latheon
test chain.

## Circuits

| Circuit | Purpose | Constraints | Public inputs |
|---|---|---|---|
| `circuits/withdraw_v6.circom` | V8 withdrawal | 11,611 (5,449 non-linear, 6,162 linear) | 4: root, nullifierHash, ctx, extDataHash |
| `circuits/disclose_v2.circom` | V8 selective disclosure (no nullifier) | 1,210 (528 non-linear, 682 linear) | 3: commitment, disclosureTag, auditorNonce |
| `circuits/disclose_link.circom` | V8 receipt or reserves (reveals the nullifier) | 1,815 (792 non-linear, 1,023 linear) | 5: commitment, nullifierHash, ctx, auditorNonce, disclosureTag |

Design: `docs/v8-design.md`. Circuit tests: `test/circuits-v8`.

## What was done (24 November 2026)

- Compiled with circom 2.2.3 and circomlib 2.0.5, default optimisation.
- Powers of tau: BN128, power 14, the same phase-1 file as withdraw_v4 and withdraw_v5 (`circuits/ptau/pot14_final.ptau`,
  SHA-256 `6e8b9e9d07aae29873729caf56cdbc718ced8a4523d7a7b5f7a5890e3f290144`). Phase 1 is circuit-independent.
- Phase 2: for each circuit, one contribution named `dev-ceremony-v8-phase2`, with 64 bytes from `/dev/urandom` as
  entropy, run by a single operator (Claude, the AI assistant used in development, in a temporary cloud sandbox) with
  snarkjs 0.7.6. The intermediate files were deleted; nobody can show that the randomness is gone, which is exactly what
  a public multi-party ceremony exists to solve.
- `snarkjs zkey verify` against the r1cs and the ptau: `ZKey Ok!` for all three.
- Verifiers generated by snarkjs 0.7.6 from these keys, with the contract renamed and the pragma pinned to 0.8.39:
  `contracts/WithdrawVerifierV6.sol`, `contracts/DiscloseVerifierV2.sol`, `contracts/DiscloseLinkVerifier.sol`.
- `test/native-v8` passes with these keys and this verifier (`DEV_KEYS=1 npm test`).

Matched sets (always used together): `circuits/build/<circuit>/<circuit>.wasm` + `<circuit>_final.zkey` +
`verification_key.json` + the verifier contract above.

## Checking the keys yourself

```
git clone --depth 1 https://github.com/latheon-network/Latheon && cd Latheon
npm install --no-save circomlib@2.0.5
mkdir -p lib && ln -s ../node_modules/circomlib/circuits lib/circomlib
for c in withdraw_v6 disclose_v2 disclose_link; do
  circom circuits/$c.circom --r1cs -l lib -l circuits -o /tmp
  npx -y snarkjs@0.7.6 zkey verify /tmp/$c.r1cs circuits/ptau/pot14_final.ptau circuits/build/$c/${c}_final.zkey
done
```

Needs circom 2.2.3 and Node.js (Linux or macOS; on Windows use WSL). Expected: the constraint counts above, and for each
key `contribution #1 dev-ceremony-v8-phase2` and `ZKey Ok!`. This proves that the keys match the circuits and the
phase-1 file; it does not prove that the operator destroyed the phase-2 randomness. Gamma is the G2 generator in every
key (snarkjs default, as in Tornado Cash and in the earlier Latheon keys).

## Before any real value

An independent review of the circuits (the questions in `docs/v8-design.md` §11 are still open), then a public
multi-party ceremony with independent, named participants. Every circuit change means new keys, new verifiers and new
pools.
